# 独立新门店泛化集：采集与验收方案 v1.0

日期：2026-11-12 ｜ 状态：草案（待采集渠道/权利门确认）
依据：GPT 终审（GPT_RESULTS_ANSWER.md）"独立泛化是真正前沿" + 设计文档 §4.4 + COLLECTION_REPORT/MAP_POI_REPORT 缺口。

## 0. 为什么需要它（问题定义）
当前 330 评估集（30 正例 / 24 正例门店组）的所有结论都是**探索性**的：
- v2 加强指令在 13/13 定向回归通过，但全量复测无净提升——**规则开发见过这些样本**，无法证明泛化。
- 配对 Bootstrap 所有系统对 ΔF1 跨 0——样本量不足以区分系统。
- GPT 三条不可豁免门槛之一：**v2 重跑不得称独立泛化验证**。

独立泛化集 = **门店组隔离、prompt 冻结后执行、规则开发从未见过**的新样本集。它是把"探索性增益"升级为"可复用方法体系"的唯一证据层。

## 1. 核心设计原则（硬约束）
1. **门店组隔离**：新集 store_id 与现有 330 的 24 个正例组 + 322 总组**零交集**；同店多张作跨视角样本但整组同进同出。photo_family 双重隔离（sha256 + 256bit dHash Hamming≤12 跨源去重）。
2. **prompt 冻结**：采集与标注全程**冻结 E10 v1 指令 + E8-G 融合权重/阈值**（不用 v2 加强指令——它已被证伪且过拟合）。新集只用于**验收**，绝不回流改规则。
3. **盲标**：双人独立盲标 + 第三方裁决（设计文档 §4.4 金标准）；VLM 裁决仅作推理证据，不作训练/金标准标签。
4. **权利门**：逐张 rights 审查；G0/G1 未过前仅可链接、探索性评估，不训练不部署。
5. **预注册**：采集前冻结验收指标与通过阈值（§4），避免事后挑选。

## 2. 目标样本量与覆盖（统计效力驱动）
现状 24 正例组 → Wilson P 下界仅 64%。要把正例召回 CI 收窄到 ±10% 量级，需 **≥40 个独立正例门店组**（新增 ≥16–20 家，与现有零交集）。

| 维度 | 目标 | 理由 |
|---|---|---|
| 独立正例门店组 | ≥40（新增≥16–20） | 收窄召回 CI；GPT 统计效力要求 |
| 每店照片 | 2–4 张跨视角 | 正面/斜侧/远距/夜景，测鲁棒性 |
| 版型簇覆盖 | CS-01..06 全覆盖，**重点补 CS-02 书法体 / CS-06 超市型**（现各仅1张） | 薄簇是 L1 瓶颈 |
| 地域 | ≥4 省（现集中浙江+福建南平） | 地域外推 stress |
| 负例 | ≥150，含竞品/同名异业/渲染素材/室内/logo | 与正例比例≈1:4，匹配业务先验需另议 |
| 困难负例 | 竞品≥30、同名异业≥20 | 测特异性（E10 拒识核心价值） |

**诚实边界**：40 组仍属有限样本；本方案目标是"把探索性证据升级为初步泛化证据"，不是"证明生产级准确率"。后者需更大规模 + 权利门 + 持续监测。

## 3. 采集通道（按可行性排序）
**重大突破（2026-11-12，用户提供高德 Web服务 key）：采集不再依赖外部，可自主批量执行。**

| 优先级 | 通道 | 可行性 | 依赖 |
|---|---|---|---|
| **P0** | **高德 Web服务 REST 搜索** `restapi.amap.com/v5/place/text` | **已验证，无反爬无需浏览器，搜索直接返回 photos[].url** | API key（已有） |
| P1 | 品牌方门店台账（驰骋控股加盟清单） | 最高质量、可补薄簇/确认版型 | 需品牌方提供（外部，可选增强） |
| P2 | getPoiInfo（浏览器会话）/ 社交平台 | 补充长尾 | 反爬/权利更复杂 |

**REST 搜索关键参数**（实测）：`keywords=左邻右舍` + `types=060200`（便利店类型过滤，排除小区/餐馆）+ `region=城市` + `city_limit=true` + `page_size=25&page_num=N`（分页，同请求最多200条）+ `show_fields=photos`（直接返回图片地址）。
**实测产量**：杭州一城 148 家便利店型 POI（122 带照片，274 图）；分页前首页仅25条会漏80%。图片 store.is.autonavi.com/showpic 直接下载无反爬。
**限流**：个人 key QPS 配额低（CUQPS_HAS_EXCEEDED_THE_LIMIT），脚本已加 0.4s 间隔 + 退避重试。
**精度**：types=060200 后 37/39 POI 为便利店；视觉抽检 39 张首图约 22 真门头/4 室内/3 同名异业/10 不清——仍须逐张全分辨率核验。

**已验证可复用管线**（MAP_POI_REPORT）：360/百度发现 POI ID → getPoiInfo 取 gallery → 下载 category=门头 → 全分辨率视觉核验品牌真伪 → sha256+dHash 去重 → 赋 store_id/photo_family/geo_bucket。
**陷阱（必须沿用）**：① 同名无关实体泛滥（住宅小区/园区/商贸城/村庄）→ 逐张核验；② 高德 category 不可全信（标"门头"可能是货架）→ 视觉核验；③ 公开图大量转载 → 以唯一代表数为准，不凑张数。

**采集脚本**：`data/collect_independent.py`（已实跑验证）。
用法：`python3 collect_independent.py --key <KEY> --cities 杭州,金华,... --types 060200 --out gen_full`
管线：REST 搜索（分页+类型过滤+限流重试）→ 下载 photos → sha256+dHash(Hamming≤12) 去重（含跨现有491组）→ store_id 隔离校验 → 候选登记（rights=pending_review, label=unlabeled）。
备用 getPoiInfo 通道（裸 urllib 被反爬，需 CDP 9222 浏览器会话）：
```js
const r = await fetch(`/ssr/api/getPoiInfo?id=${poiId}`, {credentials:'include'}).then(x=>x.json());
// 遍历 r.data.photo.gallery 提取 {url, type}；只留 type 含"门头"。
```

## 4. 预注册验收协议（采集前冻结）
**冻结对象**：E8-G 融合 s=0.4·CLIP+0.4·DINO_mc+0.2·probe，thr=0.636379（真阈值，strict >）；E10 v1 四态指令；模式 A/B 定义。

**主指标**（新门店组上）：
- 模式 A 与模式 B 的 P/R/F1 + 门店级 Bootstrap 95%CI（B=2000，seed 固定）。
- **配对 ΔF1（B−A）+ 95%CI**：是否跨 0。
- 正例召回 Wilson CI（驱动样本量）。

**通过判据（预注册，探索性）**：
- 必要条件：模式 A 或 B 的 F1 点估计 ≥0.85 且召回 CI 下界 ≥0.70（不低于探索集表现量级）。
- 泛化信号：新集 F1 与探索集 F1 差值在配对 CI 内不显著下降（无严重过拟合证据）。
- **不预设"B 必须优于 A"**——若仍跨 0，结论就是"两者等效，按业务错误成本选"。

**错误成本分层（GPT B 项要求）**：竞品误MATCH / 平面logo误MATCH / 真门店误拒 / UNKNOWN回退误纳，分别计数，不合并成 FP。

**禁止**：用新集结果回头调 prompt/权重后再报"泛化"——那会污染独立性。任何规则改动须另建第三版集。

## 5. 标注与治理流程
1. 采集 → 去重 → 赋 store_id/photo_family/geo_bucket/neg_type。
2. **双人独立盲标**（不知对方标签、不知模型预测）→ 不一致交第三方裁决 → 金标准。
3. 权利逐张审查（来源/license/授权）→ rights_status；G0/G1 门禁。
4. 冻结模型盲测 → 预注册指标 → 报告（标 measured vs 推断）。
5. 全程 VLM 裁决=证据，不进训练标签；合成数据 self_created/synthetic_train_only。
