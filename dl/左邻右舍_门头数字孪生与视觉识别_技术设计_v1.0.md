# 左邻右舍便利店门头：数字孪生驱动的少样本视觉识别系统

**技术设计文档 v1.0（研究与工程立项版）**  
研究截止：2026-11-11｜文档日期：2026-11-11  
状态：**设计可评审 / 品牌真值未封存 / 尚未执行模型实验**  
主题：门头视觉指纹、参数化数字孪生、合成数据、细粒度检索、开放集分类、加盟业务标签核验  
建议实施周期：8 周，分门禁决策

> **项目结论。** 不建议“找 30–50 张网上图片 → 全图 CLIP 向量 → 直接输出加盟类型”。建议先独立解决“视觉版本是否可区分”（T1）与“视觉版本能否识别加盟合同”（T2）两道问题；以少量真实门头建立证据基准，以 2D/2.5D 参数化数字母本生成有真值的反事实合成样本，比较 OCR/模板、CLIP、SigLIP 2、DINOv3、局部多向量检索与轻量监督适配；只在独立真实照片上验收，允许拒识未知设计。

## 0. 执行摘要和决策清单

### 0.1 核心问题

现场照片中的一个视觉对象（门头）可能同时承载至少四种不同信息：①是否属于“左邻右舍”品牌；②属于哪个已确认的品牌形象版型；③是否存在 PLUS 字样、标识版本、字体、主色、色带等视觉特征；④门店的合同加盟类型、区域代理、经营方式等业务事实。**①–③可在视觉上学习，④必须有经营主数据或有出处的业务映射，不可由图片自动“推定真值”。**

### 0.2 提案决策

| 决策 ID | 建议 | 依据 / 限制 |
|---|---|---|
| D-01 | 双任务建模：视觉形态 V；业务属性 Y | 同形不同合约时，仅凭图像存在不可辨识性 |
| D-02 | 2D 参数化母本先行；2.5D 次之；完整 OpenUSD/RTX 后置 | 关键差异可能只是几处标识，先验证信息贡献 |
| D-03 | OCR/规则设为强基线，不默认大模型胜出 | “PLUS”等显式符号常可直接检测 |
| D-04 | 冻结 DINOv3 / SigLIP 2 并行测试，CLIP 作锚定基线 | 模型优劣必须在本任务的独立数据上验证 |
| D-05 | 全局向量召回 + 局部 ROI 重排 + 文字证据 | 细微门头差异常被全图语义平均稀释 |
| D-06 | 留出真实门店测试集；合成照片不得充作真实验收集 | 避免 sim-to-real 乐观偏差和同店泄漏 |
| D-07 | 新版本触发“未知/待审”，不强制落入旧类 | 新门头、混搭、非授权装修都可能出现 |
| D-08 | 先证明合成数据的增量，再扩充渲染规模 | 最大化每张真实照片带来的增量价值 |

### 0.3 八周后预期交付（条件性）

交付门头标签本体 v1、公开样本清单与权利状态、母本与生成器 v1、合成数据 manifest、冻结数据划分、基线/消融实验报告、模型与索引 Demo、开放集拒识与人工审核队列、可复现环境、失败案例册、最终 Go/No-Go 裁决。**不承诺 8 周后必然达到商用准确率**；若品牌规则或独立真实样本不足，应结案为研究底座/No-Go，并保留数据与方法资产。

## 1. 业务事实、证据等级与待确认事项

### 1.1 已核实的公开事实

1. 驰骋控股集团官网说明，“左邻右舍”为旗下连锁便民店品牌，始创于 2003 年，采用特许加盟经营模式；官网同时经营“生活驿站”另一品牌，应在样本采集中严格排除两者混淆。官网加盟介绍说明加盟门店需要统一品牌形象装修。[S1][S2]
2. 驰骋官网“形象标准”页面可检索到“简约版 / 标准版 / 都市版”三个名称，但仅靠网页检索结果，**尚不能逐一证明它们均为左邻右舍专属门头，也不能证明对应哪种加盟合同**。应取得相应官方图像与业务解释后才冻结标签。[S3]
3. 公开报道或图片搜索中能见到红蓝色带门头、带 PLUS 字样门头、不同立面与招牌布局；这些是**可观察视觉属性**，不是经认证的加盟模式。[S4]
4. 官网截至 2026 年 1 月披露的加盟门店数量用于说明业务规模，并非本项目当前可用样本量，不能把公开报道里的门店数当训练数据规模。[S1]

### 1.2 证据四级（禁止混用）

| 等级 | 依据 | 可用于什么 | 不能用于什么 |
|---|---|---|---|
| E0 观察 | 图片上肉眼可见的色带、PLUS 字样、中文招牌 | 视觉属性的候选标注 | 官方形象版型或合同事实 |
| E1 公开文本 | 官方官网文字、可信报道 | 候选品牌/形象类别，构建待核清单 | 未出现的图文对应和合同映射 |
| E2 已审核视觉证据 | 官方形象图、门店照片 + 双人核对 + 来源记录 | 视觉版本真值与母本构建 | 经营合同事实 |
| E3 业务金标准 | 授权的门店主数据、签约政策、版本生效时间、业务责任人签认 | 加盟类型映射和业务验收 | 超出授权范围的披露 |

**当前状态：** E0/E1 已具备若干证据，E2 尚未达到多类别可靠样本量，E3 未取得。任何“PLUS = XX 类加盟”“都市版 = XX 合同”均应视作未经证实。

### 1.3 两个不可合并的问题

- **T1 视觉可区分性：** 给定图像 X，预测视觉类别 V，并能返回支持其判断的图像片段和历史近邻。
- **T2 业务可识别性：** 当且仅当有核实的映射 m(V, 生效时间, 其他条件) 时，推断真实业务标签 Y。若 P(Y|V) 明显非单峰或映射过期，系统必须输出“不能仅凭门头判断”。

可量化的前置检查：按视觉类别统计业务标签混合程度（列联表、条件熵 H(Y|V) 与各类别纯度）；若同视觉类别出现多个真实加盟类别且无补充可观测变量，禁止图像单独承担 G2。

## 2. 项目范围与非目标

**范围内：** 单张照片/巡店照片、招牌裁剪、品牌鉴别、视觉形态检索、已知版型识别、未知版型拒识、基于证据的加盟类型映射、人工审核与索引增量更新。

**首阶段非目标：** 仅凭一张照片识别合同条款、认定违法加盟、识别门店营业状态、建立整街区高保真 3D 数字城市、自动生成未经授权的品牌素材并对外分发、无人复核地用于处罚或签约决策。

**服务模式：** 一张输入图片可以包含多门店；检测层可给出多个候选招牌，用户/审核员确认主目标。图像过暗、遮挡严重、品牌标志不可见，应先报告低质量而不是强行分类。

## 3. 假设、因果结构与研究设计

### 3.1 研究假设（可被证伪）

- H0：显式标志 + OCR + 规则/模板足以解决主要已知类；复杂模型没有有意义的增量（需作为竞争性假设）。
- H1：门头裁剪/透视校正相对全图显著改善真实域 Macro-F1 或检索 mAP。
- H2：结构敏感表征（DINOv3 等）或局部 ROI 多向量，比单个全局 CLIP 向量更能识别细微版型差异。
- H3：在**相同真实样本预算和训练步骤**下，真实 + 受控合成比仅真实更好；纯合成可能失败，允许得到负结果。
- H4：类别因素和背景/天气/视角分离的反事实生成，比无差别随机生成更稳健。
- H5：拒识/人工审核策略可显著降低未知类别被错误自动接纳的风险。
- H6：即使 H1–H5 为真，视觉形态不一定足以判定真实合同类型；T2 可独立失败。

### 3.2 因果与捷径

生成过程定义为 X = Render(V, B, C, L, O, Q, A)，其中 V 是版型（允许与 Y 不同）；B 建筑/街景；C 相机；L 光照；O 遮挡；Q 摄影与压缩质量；A 可选的广告、装饰、老化。真实域中，地区、时间、渠道和门头版型可能相关，模型容易学习背景捷径。合成器必须使用跨类共享的环境变量分布，使 P(B,C,L,O,Q|V) 在设计上尽量对齐，并做“固定场景换 V”与“固定 V 换场景”的反事实配对。

## 4. 数据资产与公开样本采集

### 4.1 首轮 30–50 张的准确定位

30–50 张公开实拍是**种子集/可行性观察集**，不是足以证明商用可用的最终金标准。采集目标优先计入**独立实体门店数**，而不是下载图片张数；同店多张仅作为跨视角鲁棒性样本。应尽可能覆盖不同城市、年代、昼夜、斜拍、横竖幅、遮挡和疑似设计版本。若最终只找到不足 30 张可核验独立图片，必须明确记录缺口，不能通过转载重复图片补数。

### 4.2 采集来源优先级

1. 官方官网官方版型图 / 品牌 VI / 招商页（先查可使用权限）。
2. 可信新闻报道附带的门店实拍（记录原始记者/媒体出处与时间）。
3. 地图 POI 商户图 / 社区商业图片（逐张确认显示内容、使用条款与拍摄位置）。
4. 加盟平台/自媒体图片（较低证据等级，检测重复、营销渲染、拼接与误命名）。

对同名无关店、生活驿站、效果图、AI 生成疑似图、缺失主体的图片，不纳入真实测试集。可留作负例/无效样本，但需独立标记。

### 4.3 样本最小数据字典

| 字段 | 数据类型 | 含义与约束 |
|---|---|---|
| image_id / store_id | UUID / string | 图片唯一标识；实体门店匿名 ID；store_id 未知时必须为空并报告 |
| src_url / landing_page | URL | 原始图链接与出处网页，采集时间戳 |
| source_license / rights_status | enum | 已授权 / 待审核 / 仅可链接 / 不可用于训练 |
| sha256 / perceptual_hash | hex | 字节级与近重复检测；裁剪变体保留 family_id |
| source_group / photo_family | string | 同站转载链、同源图/镜头组，防止跨分割泄漏 |
| capture_date / geo_bucket | date / string? | 未知则置空，不猜具体拍摄日期或位置 |
| brand_state | enum | left_right / other_brand / uncertain |
| visual_style_id | nullable ID | 经审核的版型编码，未证实用 unknown，不用模型猜的类当真值 |
| observed_attributes | object | PLUS、红蓝色带、双语副标、宽高比等多标签 |
| franchise_type / mapping_evidence | nullable | E3 审核的业务标签和规则依据；默认 null |
| storefront_bbox / sign_polygon | coordinates | 检测框、四点定位、裁剪质量与可见性 |
| reviewer_a / reviewer_b / adjudicator | ID | 独立盲标与裁决日志 |
| split / evidence_level / image_quality | enum | 严格隔离与证据回溯 |

### 4.4 真值治理

- 双人独立标注不少于所有正式金标准图片；分歧由第三方裁决，并报告一致性（Cohen’s κ 或 Krippendorff’s α）；独立复核人数不得以模型自身充当。
- 新版型首次出现时先建“候选簇”，审核后授予稳定 style_id；不要用颜色簇直接命名“简约/标准/都市”。
- 按实体门店和图像家族同时分组，保证 train/val/test 的 store_id、photo_family 不交叉；地理/时间外推数据另建独立 stress set。
- 数据版本冻结：real_manifest_vX、label_ontology_vX、split_vX，SHA256 哈希、审核人、脚本版本全可追溯。
- 对仅可网页链接的图片，样本库保留 URL 与证据，不自动下载、再分发或用于模型训练；对门店访客人脸、车牌等执行最小化与脱敏。

## 5. 门头本体与分类体系

采用分层、可演化、可审核的 Ontology。

| 层 | 字段/枚举 | 注释 |
|---|---|---|
| L0 | brand_id: 左邻右舍 / 生活驿站 / 其他 / 不确定 | 先品牌鉴别，防止集团同门店品牌混淆 |
| L1 | style_id: verified_style_001... / unknown | 官方版型名称需 E2 对应，不能预填为已证实 |
| L2 | components: logo_box、PLUS、secondary_text、band、frame、lightbox | 局部多标签，支持缺失/遮挡/不确定 |
| L3 | condition: 改造、老化、灯箱熄灭、遮挡、拼接、非标准 | 不等于类别；可能影响识别 |
| L4 | franchise_type / operator_mode / region_contract | E3 主数据字段，独立于 L1/L2 |
| L5 | review_status: auto / human_required / confirmed / revoked | 输出治理标签 |

特殊设计：门店可能处在门头换新过渡期，老标与新标并存；允许 multi-style / hybrid 标记，不强制单标签。任何 style_id 都必须带版本生效范围以及冲突证据。

## 6. 参数化数字孪生：母本与场景生成

### 6.1 建模选择

- **M0：2D 矢量母本。** 使用 SVG/Canvas/参数化图层表示招牌主标、文字、框、色带、结构比例；在授权的真实街景背景上做四点透视合成/遮挡和摄影退化。优势：低成本、标签/边界可自动导出。
- **M1：2.5D 母本。** 招牌厚度、灯箱侧壁、门框、玻璃反射、悬挂侧标、遮挡层、夜景照明。仅当 M0 的真实泛化不足且误差与几何/光照相关时启动。
- **M2：OpenUSD/RTX 全 3D。** 用于反射复杂、悬浮招牌、极端斜视/夜景或立面几何相关性很强的场景；需进行成本/增量价值论证，不是默认路线。[S10]

### 6.2 母本 Schema（核心字段）

```yaml
asset_id: visual_style_001
brand_id: zuolinyoushe
asset_status: candidate_unverified    # verified only after official reference review
reference_evidence_ids: [E2_PENDING]
logo: {asset_hash: null, bbox_norm: [0.18, 0.16, 0.48, 0.58]}
plus_badge: {presence: false, bbox_norm: null}
main_band: {color_rgb: [35, 95, 190], ratio_h: 0.22}
secondary_band: {color_rgb: [205, 45, 60], ratio_h: 0.08}
text_layers: []
facade_geometry: {sign_depth_m: null, aspect_range: [3.0, 8.0]}
valid_transform_ranges: {yaw_deg: [-40, 40], pitch_deg: [-15, 15]}
model_evidence: {approval: pending, reviewer: null, signed_at: null}
```

数值只代表**技术结构示例，不是左邻右舍官方 VI 标准**。真实母本的颜色、Logo 结构、字体、灯箱比例必须由已授权参照标定；“PLUS”作为可观察属性不能擅自推成合同类别。

### 6.3 可控与不可控变量分离

- 类别因子：招牌版型、标识组成、主色条纹组织、文字排布、边框比例（由真实类约束）。
- 无关因子：视角、拍摄距离、分辨率、曝光、夜间与雨天、反射、运动模糊、压缩、遮挡、背景、店外广告、门前车辆。
- 现实合法组合：强夜景×灯箱光源、雨天×玻璃反射等条件需要有合理联动；不可随机造出物理或品牌不合理的“怪样本”。
- 背景来源：优先自主拍摄、许可图片、合法合成场景；受版权限制的街景仅保留访问链接与版权记录。

### 6.4 反事实样本组

**CF-1 类别干预组：** 固定背景、机位、光照、遮挡和相机，只替换一个已核验的版型差异；训练模型对真正的版型变化敏感。  
**CF-2 环境干预组：** 保持版型完全一致，独立随机化天气、建筑、拍摄视角、非品牌广告与遮挡；训练模型对这些干扰不敏感。  
**CF-3 局部破损组：** 使关键文字部分被遮住，或老化/污损；模型应降低信心、选择拒识。  
**CF-4 非法搭配检测组：** 交换局部 Logo、位置、颜色形成不符合已核实 VI 的组合；标记为 synthetic_unknown / anomaly，而不是冒充真实已知门头。

**标签不变性边界：** 如果改变的特征本身就是类别定义的一部分（例如 PLUS 标记），不能把它当成无关增强；反过来若品牌手册允许同一版型有多个角标，不能误当不同合同类。所有关键增广要有规则白名单。

### 6.5 标注随生成（by construction）

每张合成图片自动产生 class_id、style_id、landmark boxes、sign polygon、semantic mask、camera parameters、domain factors、render config、master asset hash、generator commit、随机种子及 image sha256。采用三层 QC：参数合法性检查、渲染后可读性检查、随机人工审样；**合成标签只对自身生成的语义有效**，不替代真实世界的验证。

## 7. 视觉识别系统架构

```text
输入照片 / 多门店街景
    │
质量检测 → 目标商铺识别 → 门头检测 / 多候选 → 四点校正 + 长宽比保留
    │
    ├─ OCR：品牌、PLUS、英文副标、字符位置、文本置信度
    ├─ 视觉全局：CLIP / SigLIP 2 / DINOv3 归一化向量
    └─ 局部 ROI：Logo、角标、条纹、文字区与自动 ROI token
    │
召回：FAISS 近邻 Top-K + 规则候选集（可按品牌过滤）
    │
重排：局部多向量匹配 + OCR 证据 + 质量条件校准
    │
选择性预测：已知版型 / 未知版型 / 图像无效 / 需人工审核
    │
业务映射：若有 E3 规则且适用 → 业务类别；否则“视觉可判、加盟未知”
    │
证据卡：相似样本、依据区域、模型+规则版本、审计日志
```

### 7.1 基线优先顺序

B0a：色带/Logo 模板与 OCR 规则；B0b：全图 CLIP；B1：裁剪图 CLIP；B2：SigLIP 2 冻结图像编码器；B3：DINOv3 冻结编码器；B4：最佳基础表征 + ROI 多向量；B5：B4 + OCR 融合；B6：B5 上轻量度量学习/Adapter。若 B0a 已经达到目标，保留其作为部署主干或联合冗余通道。

### 7.2 全局 + 局部 + OCR 融合

对候选类别 c，示意评分：

S(c|x) = w_g s_global(x,c) + w_l s_local(x,c) + w_o s_ocr(x,c) + w_q s_quality(x,c)。

- s_global：L2 归一化向量的余弦检索，相似样本与 class medoid 双视角评估，避免简单均值混杂多个门头变体。
- s_local：经位置或语义区域约束的 patch/ROI Top-K matching；应与“只在类相关 ROI 上比较”的强基线竞争。
- s_ocr：文字识别内容、文本框位置、字体/标识置信度；字符漏识别不能当作“该标识不存在”。
- s_quality：质量与可观测性，用于调节置信度而不直接学习“模糊=某类别”。
- 各分量先在验证集独立校准尺度，再拟合融合权重；缺失 ROI、OCR 失败时使用 mask/缺失通道，不拿 0 伪装成负证据。

### 7.3 检索索引和类别扩展

起步可用 FAISS FlatIP 精确余弦检索；数据量增大后再评估 ANN 的召回损失。需要保存模型版本和嵌入空间 ID；不同编码器向量不可直接混在同一索引。新官方门头版本经审定后，先更新参考样本与原型即可支撑检索；是否重训应依真实域误差再决定。相似检索给“候选与证据”，不直接提供已校准分类概率。[S9]

### 7.4 选择性预测（拒识）

拒识原因至少分四类：not_brand、unknown_style、low_quality、ambiguous_or_hybrid。阈值从验证集按错误代价选定，并在独立测试集报告覆盖率—错误率曲线、未知误接纳率与已知误拒率。阈值应分品牌/类别与质量分层检验，避免只凭 Top-1 与 Top-2 的差值设规则。**不允许在测试集上调阈值。**

### 7.5 输出 API（字段示意）

```json
{
  "image_id": "...", "brand": "zuolinyoushe",
  "visual_prediction": {"style_id": "candidate_002", "state": "needs_review", "score": null},
  "evidence": {"top_neighbors": ["img_013", "img_028"], "visible_attributes": ["plus_badge"], "ocr_text": ["左邻右舍"]},
  "business_prediction": {"franchise_type": null, "mapping_status": "NO_VERIFIED_RULE"},
  "quality_state": "valid", "unknown_reason": "STYLE_NOT_VERIFIED",
  "versions": {"model": "dino3_baseline_0", "ontology": "v1", "index": "v1"},
  "human_review_required": true
}
```

示意 API 不对应已运行推理结果，所有信心分数应在训练并校准完成后由系统生成。

## 8. 训练机制与合成比例策略

### 8.1 两阶段训练而不是直接端到端

**阶段 A（冻结表征）：** 不改变主干，做近邻、线性 probe、原型分类、OCR 规则，先确定错误结构。  
**阶段 B（可选轻量学习）：** 在冻结 backbone 上训练小投影头/Adapter；对同版型跨场景正对、不同版型同场景难负对施加 SupCon/Triplet 风格的度量损失，并与真实有标签样本的监督分类交叉熵联合。  
**阶段 C（仅必要时）：** 有足够真实数据且前两阶段证明瓶颈在表征时才考虑 LoRA/部分层微调，并与计算成本和漂移风险一起评估。

### 8.2 合成数据数量不是 KPI

初始试验按每个**经证实**的版型生成多个场景并执行 100 / 300 / 500 张量级的剂量消融（只是设计探索量，不是经验最优）。设置 synthetic:real 采样比、训练步数、真实图片暴露次数受控；**对照组需要同等训练更新次数**，否则无法归因提升是数据本身而非更多计算。训练集不得包含测试门店的裁剪/素材/背景衍生物。

### 8.3 合成数据五类失败及侦测

| 风险 | 机制 | 检验 |
|---|---|---|
| 纹理捷径 | 每类固定一个街景或一个色彩基调 | 跨类共享环境与背景置换，背景探针 |
| 错误标记 | 母本对应关系错误、Logo 拼接不准确 | 官方 E2 对照、双人母本验收 |
| 域差 | 合成边缘过于干净、字体/反射不真实 | 真实集分层性能、合成单独训练迁移 |
| 不可能样本 | 类别关键元素被非法随机删除 | 类别不变性白名单、生成配置合法性门禁 |
| 合成过拟合 | 在合成验证集高分，真实街景下降 | 真实门店闭集/开集双测试、反事实反转集 |

## 9. 实验矩阵、统计计划和停止规则

### 9.1 冻结流程与消融表

| 实验 | 处理 | 回答的问题 |
|---|---|---|
| E0 | OCR/模板/规则 | 无深度适配可达到什么效果？ |
| E1 | 全图 CLIP | 常规图文模型基线 |
| E2 | 同 backbone 的裁剪图 | 排除背景干扰带来多少增量？ |
| E3 | 同输入 SigLIP 2、DINOv3 | 哪种视觉表征适合此任务？ |
| E4 | E3 优胜 + ROI token | 多向量局部信息是否必要？ |
| E5 | E4 + OCR | 文字符号是否额外有效？ |
| E6 | 少量真实监督轻量训练 | 不使用合成时的公平上界 |
| E7 | 等真实样本数 + 未整理合成 | 普通合成有无增量？ |
| E8 | 等真实样本数 + 类别/环境解耦 | 受控合成是否改善真实域？ |
| E9 | E8 + 反事实成对生成 | 反事实是否带来独立贡献？ |
| E10 | 留一版型未知 + 反事实异常 | 拒识未知设计和非标准门头 |

每个 E 的输入样本、seed、checkpoint、图像预处理、冻结版本、参考样本库、索引结构、超参数、评测脚本都需要写入 manifest。涉及训练随机性的比较建议至少 3 seeds，置信区间使用实体门店层面的 bootstrap 而不是按相似图片独立重抽。

### 9.2 分组策略

- train/val/test 按 store_id 与 photo_family 双重 GroupSplit；去重图片和同一店多年照片需要同一组或专门的跨时实验；同源素材背景不得穿越合成训练和真实测试。
- 固定测试集只包含可合法用于评估的真实图片；合成数据只放训练和合成诊断集，不能提升实际测试规模。
- 按地域、年份、白天夜晚、角度、图像大小与遮挡程度切分报告；另设“未知设计类留一”试验。
- 类别不足以划出可靠训练/测试时，不得发布整体 Macro-F1 的高置信结论；允许只发布案例、区间宽度和可行性判定。

### 9.3 主指标与次指标

| 指标组 | 指标 | 关键说明 |
|---|---|---|
| 分类主指标 | Macro-F1 + 每类 Recall/Precision | 防止多数类掩盖少数类 |
| 检索 | Recall@1、Recall@5、mAP | 只从训练/参考库检索，不允许含测试图复制 |
| 业务价值 | 已确认业务类的精准率 + 映射覆盖率 | 只有 E3 样本才能计算 |
| 开放集 | Unknown Recall、False Accept Rate、AUROC | 闭集高分不能替代未知识别 |
| 选择性分类 | 风险—覆盖率曲线、自动误判率、人工复核率 | 直接对应运营成本 |
| 迁移能力 | 实拍—合成差、跨地区/设备/昼夜降幅 | 监控 sim-to-real gap |
| 生产成本 | 每样本标注时长、审核工时、推理时延、单图总成本 | 合成高分不等于经济可行 |

### 9.4 门禁与 Go / No-Go

**G0 真值可行：** 至少存在两个可从 E2 图证独立确认的视觉类别，并有能开展独立真实评估的实体门店样本；未满足不进入“正式分类精度”的宣称。若业务映射需 E3，T2 未具备则业务输出始终 null。

**G1 数据质量：** 参考/测试集去重与来源核验 PASS；训练和测试实体门店无交叉、衍生素材无交叉；两人审核有分歧处理机制。

**G2 表征增益：** 以 OCR/模板和全局表征中表现最强者为强基线，局部/合成路线的真实域改善须有预设最小有意义差异（初拟 Macro-F1 +0.03 的绝对增量，仅为立项讨论阈值）、配对区间及可重复性；若样本量不足无法支持统计结论，明确 INCONCLUSIVE 而非 PASS。

**G3 安全拒识：** 在独立未知版型/异常组合上优先达成误接纳率风险预算；初拟 ≤2% 为业务讨论值，必须依据业务误判成本与足够未知样本重新审定。若不满足，系统仅作检索辅助，不自动分类。

**G4 业务映射：** E3 映射审定，历史生效/失效日期、例外合同、同版多合同均已检查；未通过只能输出“门头视觉类别”。

**G5 运行与权利：** 训练与展示素材授权合规、隐私脱敏、模型许可核验、模型哈希可复现、部署回滚可用。

**禁止行为：** 将没有真实测试集的合成集高分当作成功；从公开图中猜合同类；根据测试集调阈值；把“图片数量”当“独立门店数”；仅报告总体 Accuracy 而不报告拒识/失败类。

## 10. 标注成本与经济性模型

核心业务指标是 **达到相同真实域错误率所需人工标注和审核工时**，不是合成图数量。

定义：

- C_real = 采集许可/购买 + 真实图审核 + 二人标注 + 冲突裁决。
- C_twin = 官方版型资料整理 + 数字母本制作与审核 + 合成器开发。
- C_synth = 渲染或合成计算 + 抽样质检 + 存储管理。
- C_ops = 推理、审核未知图、漂移监控与版本维护。

比较相同业务风险预算下：TCO_baseline = C_real + C_ops，TCO_twin = C_real_reduced + C_twin + C_synth + C_ops_new。用学习曲线测量达到目标风险需要多少**独立真实门店标签**，计算标注工时节约率和盈亏平衡点；如果门头类别少、OCR 很有效，数字孪生可能不经济，应允许止损。

## 11. 工程实现、数据契约与可复现性

### 11.1 推荐模块

1. **Evidence Registry：** 网站链接、版权、证据等级、人工核验、哈希。
2. **Ontology Service：** 版型字典、视觉属性、多品牌排斥、业务映射规则版本。
3. **Twin Studio：** 矢量母本、变量白名单、母本审批、合成渲染及审样。
4. **Feature Factory：** 裁剪、透视校正、OCR、嵌入向量与 ROI token。
5. **Retrieval Service：** FAISS 索引、证据样本、同类多原型和索引版本。
6. **Decision Service：** 融合与拒识、业务映射、人工审核任务分派。
7. **Evaluation Harness：** 固定分割、消融矩阵、置信区间、跨域与未知类别测试。
8. **Ops：** 模型/资产版本、影子运行、事件日志、回滚和漂移监控。

```text
  tests/{golden,leakage,license,determinism,api_contract}
```

### 11.3 质量测试（至少）

- 任意样本必须能从 image_id 回到出处/许可/原图哈希；孤儿样本禁止进入训练。
- 生成器在相同代码、资产 hash、seed 和确定性设置下，输出一致标签；图片像素可允许平台差异容差并记录，不机械要求跨 GPU 位级一致。
- 批量检索中，同一图片无论放在哪个 batch，预处理和推理应一致或差异处在预定义容差内；不能把不同 batch 分数漂移当模型特征。
- 类别重命名不得改变既有 ID，业务映射需日期有效性与审核日志。
- Unknown/low_quality 等状态严禁被客户端偷偷改写成 Top-1 已知类。
- 训练、验证、测试任意跨集重复 store_id / photo_family / 近重复 hash 都触发硬 FAIL。

## 12. 部署、人工闭环与持续监控

**推理阶段**：返回分类候选与证据；对较低风险的明确视觉版本可以自动标注“视觉版型”，加盟类型仍必须满足映射规则。待审核清单按近邻冲突、未知度、质量、类稀缺度排序，人工审核后分“新类别”“旧版新场景”“图像不可用”“与总部不一致”四种处置。

**监控重点**：已知类置信度漂移、未知比例突增、地区/年代表现差、OCR 缺失率、分类与人工复核冲突、门头政策变化。阈值或新类更新先影子部署，抽样复核通过后切换索引与规则版本；保留一键回滚能力。需审慎对待街景拍摄使用条件、第三方地图版权和品牌商标的内部/商用权限。

## 13. 八周执行计划（含止损）

| 周次 | 输出与任务 | 不可跳过的闸门 |
|---|---|---|
| W1 | 官方形象/业务规则清查；标签本体；公开图收集与许可筛选 | 未确认 E2/E3 不得定义“官方合同分类” |
| W2 | 30–50 真实种子候选去重；实体门店映射；双盲标；数据分割 v1 | G0/G1，若不足则调整目标为视觉检索验证 |
| W3 | 2D 数字母本 1–3 个已核验视觉版本；类别-环境参数表 | 母本官方对照和类别不变性审查 |
| W4 | 反事实生成器、自动标注、质量门禁、合成 manifest | 合成合法性与 GT 自检 PASS |
| W5 | OCR/模板、CLIP、SigLIP 2、DINOv3、裁剪基线 | 冻结独立真实集，不碰测试阈值 |
| W6 | ROI 多向量与合成数据剂量/反事实消融 | 同真实样本预算、同训练步数/seed |
| W7 | 真实域盲评、留一未知版型、业务映射验证、统计与成本 | G2/G3/G4：不足可判 INCONCLUSIVE/FAIL |
| W8 | Demo、失败集、报告 v1、部署影子计划、Go/No-Go 审批 | G5、复现验收、报告与资产封存 |

**止损点：** W2 若真实视觉类别真值不足，先完成可检索的样本与规范库；W5 若 OCR/模板已经解决大多数有用场景，缩小深度模型投资；W7 若合成无真实增量，冻结合成研究资产而不继续扩大生成。

### 16.1 需要避免的论文误读

- POI-Loc 是 **2026-09 的 arXiv 预印本**，论文自述投稿 ICASSP 2027，不能写成已正式发表在 ICASSP 2027。
- Region-Aware CLS Token 采用 **DINOv2-reg** 为基础，不能写成已证明 DINOv3 + ROI 在门头任务更好。
- CVPR 2026 的 BOB 方法是基于生成模型的实验；本项目采用更可控的程序化母本属于**方法启发**而不是直接复现 BOB。
- 所有论文公开基准分数均不应搬用为本项目预期准确率。

## 17. 正式评审中必须回答的十个问题

1. 品牌方是否有真实门头 VI 文件与每种形象对应的合同政策？
2. “简约/标准/都市”是否确实适用于左邻右舍？有无生效时间和区域例外？
3. PLUS 是形象元素、营销标识、运营模式还是合同属性？谁提供金标准？
4. 至少能否采到两个以上经认证的视觉版型，每类有若干独立真实门店？
5. 是否有直接的 OCR/模板规则可覆盖大部分场景？
6. 合成器是否把类别与地域/背景虚假绑定？能否通过反事实对验证？
7. 是否真正按门店、拍摄家族和派生资产隔离训练/测试？
8. unknown/ambiguous/low_quality 是独立状态，还是偷偷回落为 Top-1？
9. 是否在真实集上量化了相同风险预算下的标注工时与 TCO？
10. 若 T1 通过、T2 失败，是否仍允许作为“视觉巡检/检索”资产结题？

### 18.1 未关闭的风险清单（必须透明披露）

- R-01（P0）：真实加盟类别与门头形态的映射未取得；**不得提供自动加盟合同判定**。

### 18.2 签署建议

建议批准 **8 周“研究验证”** 而非批准“即刻全自动加盟类型识别上线”。第一阶段真正的通过标准是：在版权/业务真值边界清晰的前提下，证明门头视觉类型可检索、可分类且新增版本可拒识；再单独决定是否接入加盟经营主数据。
