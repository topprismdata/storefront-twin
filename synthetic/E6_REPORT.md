## 协议
- 池：爬取候选弱标签（VLM 核验，A=正例 / B,C=负例 / D 剔除）+ registry 非 330 行（sha 级排除评测重叠）+ renders_3d 合成负例。评测 330 = 全分辨率人工核验集，门店级与池零重叠，仅打分不调参；阈值一律池内 GroupKFold(POI) OOF 选出。

## 关键发现
1. **v1 失败根因 = 负例域缺口**：池负例只有同名门头/室内，31 FP 中 23 张是 render_stock（海报/素材图）——探针没学过拒绝"有品牌字但非门头"的图。
2. **v2 补域后 FP 31→12**（render_stock 23→8），F1 0.629→0.817；仍未超 E8-G（AuPR 0.855 vs 0.926）。
3. **强互补**：E6-v2 与 E8-G 的 FN 完全不相交（img_0489 vs img_0012/0487），FP 交集仅 2/18。OR 融合（观察值，未调参）R=1.000、P=0.625、F1 0.769。
4. 训练池本身 OOF F1 0.907——池内任务近乎解决，残余差距全在跨域标定。

## 结论与建议
- E6-v2 单独替换 E8-G：**否**（精度弱一档）。
- E6-v2 作为 E10 架构的**第二召回头**（UNKNOWN 回退 = max/OR(e8g, e6)，或 VLM 救援通道第二意见）：候选成立，召回安全性提升（fallback 层 0 FN），端到端收益需下一轮全盲 VLM 批次验证。
- 阈值跨域漂移是已知弱点（池 OOF thr=0.482 在 330 上偏松）；部署前需按目标域重标定。
- 弱标签噪声 ~94-96% 正例精度；金标准 644 标注包已就绪（`data/annotation_pack/`），是精度上限的解锁项。

产物：`synthetic/vis_cache/e6/`（probe npz、eval json、disagreements）、`e6_real_probe.py`、`e6_real_probe_v2.py`。
