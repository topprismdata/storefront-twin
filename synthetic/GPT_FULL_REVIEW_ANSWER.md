# 左邻·右舍门头识别系统：独立对抗性评审

**REVISE** · 独立评审 · 2026-11-14 · 基于全量评审稿 v1.0

## 一、最终裁决

**REVISE。不批准当前版本作为生产部署验收依据，也不批准将现有指标作为品牌方的实际识别准确率承诺。**

原因不是模型效果不够好，而是目前存在三个更根本的问题：

1. **训练授权边界与实际训练工件不一致。** 文档批准的是部分真实数据进入训练，但最终模型声明使用了全部647条真实样本。
2. **评测结果与真实部署环境之间存在明显距离。** 当前负例以渲染素材为主，真实经营场景中的困难负例覆盖不足。
3. **部分验证结论存在统计口径和独立性问题。** 分组单位、评测版本、阈值和配对检验没有形成足够清晰、可独立复核的证据链。

核心判断：

> 这套系统已经完成了一个有价值的离线识别原型，但还没有证明它是一个能够在真实门店照片分布上可靠运行的品牌身份识别系统。

三个概念区分：
- 模型能够识别当前数据集中的品牌特征。
- 模型能够泛化到未参与训练的门店。
- 模型能够在真实业务采集环境中稳定识别品牌。

目前主要证明了第一项，部分支持第二项，第三项尚未得到充分证明。

## 二、§10 A–F 六项逐项裁决

| 项 | 裁决 | 维度 | 依据 |
|---|---|---|---|
| A | PARTIAL | 分数层方法 | LOSO有一定价值，但负例分布、阈值选择和随机性尚不足以支撑部署性能推断。 |
| B | PARTIAL | 证据层价值 | Mode B的收益不能证明来自VLM；现有实验也不足以证明VLM没有独立信息量。 |
| C | PARTIAL | 跨省泛化 | 江西结果支持有限的区域迁移，但只冻结了探针训练样本，不能直接等同于整个系统零江西训练。 |
| D | OPEN | 检测器路线 | 两种路线失败不构成检测技术路线穷尽，尚未完成候选框定位与证据融合的对照验证。 |
| E | PARTIAL | 部署工件 | 模型与评测分离是必要的，但模型版本、推理确定性、输入分布、运行监控等尚缺。 |
| F | PARTIAL | 下一步方向 | 不应继续优先投入模型优化，也不应启动部署试点；先解决数据权利和真实业务分布的证据缺口。 |

### A. 分数层方法：PARTIAL

**A1. 负例分布不具有部署代表性。** 391 负例以 render_stock 为主。模型究竟学会了识别真实门店的品牌身份，还是学会了区分"官方品牌视觉 vs 渲染素材/设计模板"？真实部署困难负例应包括：红蓝相似配色真实便利店、相似文字招牌、同名异业、同街区相似门头、联营/复合品牌、远距离/夜拍/遮挡/反光/斜拍、同品牌不同年代门头。这些的数量和分布未披露。

**A2. 0.916 的统计含义没有完整定义。** 需说明：micro-F1 还是门店组 macro-F1？0.80 是预先确定还是评测数据上选择？折数口径？每折是否独立重建参考图库？阈值校准是否完全在训练折内部？检索画廊与 LOSO 的隔离必须确认。

**A3. 多裁剪通道随机性 ≈0.104 不可忽略。** 需报告：同图重复运行分数方差、阈值附近翻转率、不同种子 F1、线上是否固定种子。

**A4. 向品牌方的正确表述**（建议原文）：
> 在当前647条门店分组验证样本及既定负例构成下，模型取得最高约0.916的离线F1表现。该结果反映当前数据集和评测协议下的识别能力，不代表真实业务环境的准确率或上线后的误报率。

禁止说"门头识别准确率91.6%"等。

### B. 证据层：PARTIAL

不能从"Mode B≈Mode A"推出"VLM没有独立信息量"——Mode B 也使用了 VLM 明确判词。需要四组消融：Score only / VLM only / Score+VLM(不回退) / Score+VLM+回退，同一冻结测试集比较；并报告误报漏报逐样本交集。OUT_OF_SCOPE（不属于任务）与 UNKNOWN（属于任务但证据不足）不能混为一谈——对数据治理和人工复核价值不同。架构可保留，生产价值待验证。

### C. 泛化宣称：PARTIAL

"探针零江西样本"≠"系统零江西"：s_clip/s_dino_mc 检索画廊若含江西正例即泄漏。江西 74 店高度集中（上饶47），非有空间代表性的省测试集；负例地理分布未单独披露。建议结论收窄为"在探针不含江西正例的条件下…初步显示迁移能力"。福建 9 正例更不能作全国证据。

### D. 检测器路线：OPEN

两次失败不构成路线穷尽。建议评估：D1 DINOv2 patch 相似度热图定位；D2 现成文本检测器（DBNet）+ 招牌几何特征，重点是"招牌文字区域召回率"；D3 VLM 候选区域定位（输出只作定位建议不作训练标签）+ 独立几何验证。关键原则：**不能用最终品牌判词反过来证明候选框正确**，定位器需独立人工框参照（Recall/IoU/漏检率/误定位率）。不建议立即大规模标注，先小规模独立标注路线比较。

### E. 部署工件诚实性：PARTIAL

E1 版本映射表（数据集哈希/特征模型版本/探针权重哈希/阈值依据/CLI 加载工件哈希）——否则 model_card 引用 E6-v3 评测而部署跑 e14，无行为一致性证据。E2 随机性：同图 ≥100 次重复推理一致性测试。E3 输入分布声明（最低分辨率/极端透视/夜拍/多招牌/拒绝策略）。E4 生产监控（判定占比/UNKNOWN 率/复核率/分数漂移/VLM 失败率/降级策略）。E5 CLI ≠ 完整部署件，称"离线推理原型"更准确。

### F. 整体下一步：PARTIAL

优先级：**P0 权利链与训练数据授权审计**（尤其 391 真实负例是否获训练授权；此前不得以部署为目标）→ **P1 真实业务困难负例挑战集**（100–200 真实困难负例 + 50–100 多样式正例 + 两个独立地域 + 双标注 + 仲裁 + 逐图权利；不是训练集，是独立验证集）→ P2 扩正例门店与样式覆盖（CS-02/06 各 1 张不能支持样式泛化）。**明确反对现在开展生产试点，小范围试点也不能绕过权利链门禁。**

## 三、数字不一致与统计问题

### 3.1 确定性数字问题（必须修正）

| 编号 | 位置 | 问题 |
|---|---|---|
| N01 | §2 | 51 real + 2 排除 + 26 unread = 79 ≠ 89，缺 10 条去向 |
| N02 | §4 | F1 0.905 与 0.916 并列，未说明各自阈值与聚合口径 |
| N03 | §4 | 0.87→0.916 增量 0.046，配对检验却 +0.043，口径未标注 |
| N04 | §4-5 | 241 折/322 店组/639 折，折数、样本数、店组数混用 |
| N05 | §9 | 正例店组数 24–26 口径不固定 |

### 3.2 评测单位混乱（高优先）

LOSO 每折对应一个店组？一张图？一次重训？一条有效预测？639 折与 241 折为何不一致？要求补评测单位说明表。

### 3.3 p=0 不是正确的统计报告

有限次 Monte Carlo Bootstrap 的 p=0 只说明有限重采样中未观察到符合条件的结果。应报告：重采样次数、单/双侧、零假设、计算方法、p 值有限分辨率上界。

### 3.4 置信区间独立性

正例仅 24 店组：负例数量不能替代正例独立门店数；Bootstrap 重采样必须保留店内相关性；应报告正例店组在重采样中的分布。

### 3.5 测试集反复用于指令修复（高优先）

v1 冲突 → 全分辨率仲裁 → 改指令 → 13/13 验证 → v2 全 330 重跑：13 例是开发验证集，v2 的 0.951 应标注为"**经测试集驱动的指令迭代后得到的探索性结果**"，不是独立泛化验证。应分 Prompt Development / Locked Validation / Independent Test 三段。

### 3.6 训练授权可能超范围（最高级治理问题）

§1 写"真实**正例**进入训练"，e14 实际用了全部 647（含 391 负例）——需核对治理原文与逐图授权清单；核查前 e14 不能认定具有完整训练授权链。

## 四、其他过度宣称与工程隐患

| 问题 | 判断 |
|---|---|
| 江西 0.973 | 探针零样本 ≠ 全系统零样本，宣称必须收窄 |
| 合成 820 | 合成域差距，不应作真实泛化证据 |
| RNG ≈0.1 | 可能造成阈值附近翻转，必须工程化解决 |
| 招牌定位缺位 | 固定裁剪有结构性漏检，不应直接进生产 |
| VLM 依赖 | 换模型需重建证据层基准，需版本锁定 |

OCR 审计证明"文本出现 ≠ 品牌门店身份"——品牌识别必须保持双证据（品牌身份 + 真实经营场景）。

## 五、Top-3 残余风险

1. **数据权利与训练来源不一致**（阻断级）：391 负例授权存疑；关闭条件=逐图权利/训练用途/评测用途清单 + e14 逐条匹配 + G0/G1。
2. **离线评测与真实部署分布偏差**（高风险）：关闭条件=真实困难负例挑战集 + 独立地域 + 冻结画廊 + 独立测试集 + 实际误报率 CI。
3. **统计证据链与可重复性不足**（高风险）：统一评测单位 + 固定版本 + 重做配对统计 + 独立锁定测试集 + 消除/量化推理随机性。

## 六、整改顺序

R1 权利审计 → R2 统一口径 → R3 修正统计报告 → R4 真实困难负例挑战集 → R5 消融 → R6 重做跨区域泛化（探针与画廊同隔离）→ R7 端到端部署验收。R1/R2 并行，R3 在 R2 后冻结执行。

## 八、战略性意见

当前最容易犯的错误：继续追求 F1 0.951→0.96，优化融合。真正要回答的不是"现有图片里能不能更准"，而是"放到完全陌生的城市、真实街道相似门头/复杂光线/不同距离下，能否可靠判断"。建议下一阶段命名为 **E11：真实经营环境独立泛化验证**。成功标准：无门店级泄漏证明、真实困难负例误报风险、跨地域样式泛化边界、重复运行稳定性、每项结论的数据/模型/授权/人工证据可追溯。只有这五件事成立，才有资格讨论部署。
